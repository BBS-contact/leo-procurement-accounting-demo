## 1. Purpose of this document

This document explains the exported human review package generated by the LEO procurement/accounting anomaly demo.

The exported package is a JSON file created by the local dashboard after a human reviewer records a review action.

Its purpose is to preserve:

* what LEO detected;
* what evidence was linked to each signal;
* what the risk meaning was;
* what question the human reviewer should answer;
* what human review action was recorded;
* what reviewer note was added;
* what LEO explicitly did not do.

The package is not a legal report.

The package is not a fraud accusation.

The package is not an enforcement instruction.

The package is a local review-memory artifact.

---

## 2. Why the package matters

The package demonstrates that LEO can complete the following workflow:

`INPUT → ANALYSIS → EVIDENCE → HUMAN REVIEW → EXPORTABLE REPORT`

This matters because institutional review is often lost in informal notes, emails, conversations, or disconnected files.

The package preserves review state in a structured form.

It can help an institution later answer:

* What did the system detect?
* Which evidence object supported the signal?
* Why was the signal considered relevant?
* What question was given to the reviewer?
* What did the human reviewer decide?
* Was any autonomous enforcement performed?
* Were production records changed?
* Was the canonical registry opened or mutated?

In the tested demo, the answer to all autonomous or production mutation questions is negative.

## 4. Zero-autonomy boundary

The exported package contains a zero-autonomy boundary section.

Expected structure:

```json
"zero_autonomy_boundary": {
  "autonomous_enforcement_actions": 0,
  "canonical_registry_opened": false,
  "canonical_registry_mutated": false,
  "production_records_mutated": false,
  "signing_or_key_access_performed": false,
  "external_execution_performed": false,
  "reviewer_actions_storage": "browser localStorage until this export"
}
```

Meaning:

* `autonomous_enforcement_actions: 0` means LEO did not execute enforcement.
* `canonical_registry_opened: false` means no canonical registry was opened.
* `canonical_registry_mutated: false` means no canonical registry was changed.
* `production_records_mutated: false` means no production records were changed.
* `signing_or_key_access_performed: false` means no signing keys or signatures were accessed.
* `external_execution_performed: false` means no external system execution was performed.
* `reviewer_actions_storage` clarifies that review choices were local browser state before export.

This section is essential.

It proves that the demo is a human-review layer, not an autonomous operational authority.

This structure matters because it preserves both machine-prepared review context and human review interpretation.

A finding is not just a score.

It tells the reviewer:

* what was detected;
* why it matters;
* what evidence supports it;
* what question should be answered;

## 7. Sample reviewed finding — EV-001

The tested package confirms that `EV-001` was reviewed by a human.

Expected finding identity:

```json
{
  "id": "EV-001",
  "title": "Price above benchmark",
  "severity": "CRITICAL",
  "supplier": "North Bridge Office Supplies Sp. z o.o.",
  "evidence_ids": ["EV-001"]
}
```

Expected detected signal:

```json
"detected_signal": "Observed unit price (230.00 PLN) is 2.30x benchmark median (100.00 PLN)."
```

Expected risk meaning:

```json
"risk_meaning": "The paid or proposed unit price is materially higher than the benchmark. This may be legitimate, but it requires justification such as quality, urgency, specification, or market conditions."
```

Expected reviewer question:

```json
"reviewer_question": "Is there documented justification for the price difference?"
```

Expected recommendation:

```json
"recommendation": "Escalate for human review before any institutional decision."
```

Expected human review:

```json
"human_review": {
  "action": "ESCALATE_FOR_REVIEW",
  "note": "Price requires documented justification, benchmark explanation, and procurement need confirmation.",
  "updatedAt": "..."
}
```

Meaning:

The reviewer did not approve or reject the transaction.

The reviewer escalated the finding for further review and documented why.

The recorded note clarifies what evidence should be checked next:

* documented price justification;
* benchmark explanation;
* procurement need confirmation.

This is exactly the intended LEO review workflow.

## 8. Unreviewed findings

Most findings in the tested package remain:

```json
"human_review": {
  "action": "UNREVIEWED",
  "note": "",
  "updatedAt": null
}
```

Meaning:

The findings were detected and exported, but the human reviewer has not yet recorded a review action for them.

This distinction is important.

LEO can detect and prepare many findings, but the package clearly separates:

* LEO-generated signal;
* human-reviewed signal;
* unreviewed signal.

This prevents the system from pretending that all findings have already been institutionally evaluated.
